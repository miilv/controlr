## Decision and index semantics

Read first: robot-harness `coord/DECISIONS.md:37` (D-C20) and `:41` (D-C20a),
at `219232ef47bc6ca82a05821b910df10ba3cefbd9`.
D-C20 specifies headline states 40–49 and the disclosed devseeds row 1–10.
D-C20a opens 31–39 only for one pre-registered full run after HL2 closes, with
both sides' prior-use audits required before freeze. The decision's 78-task
clean statement is Mikhail-side evidence, not a conclusion about Ilia's logs.

`harness/libero_server.py:182–207` makes `episode` the zero-based index into
`suite.get_task_init_states(task_id)`, calls `env.seed(seed)` before reset, then
`set_init_state(init_states[episode])`; absent an explicit seed, seed = episode.
A reset log is actual state use, even if no motion follows. A sweep's dry-run
result is exposure too. A CLI example, planned order, range allowed by a gate,
or synthetic fixture is not evidence of a simulator episode.

Ilia's `dojo/perception/agentic/libero.py:137–180` processes an existing capture;
it does not select or reset an init state. Its calls ledger has `fn`, `ws`,
`cell`, time and model/call statistics, but no episode/state index. Parent episode
records are therefore needed to assign an index. The install example in
`dojo/perception/agentic/INSTALL-isr-lab.md:45–53` has placeholders and no state.
