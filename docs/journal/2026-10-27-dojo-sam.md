# 2026-10-27 — SAM stream (perception bake-off): SAM 3.1 / 2.1 mask proposers, and the numbered-series count bug

Stream: SAM (perception bake-off, compute4 light1). Report with all tables:
[../experiments/2026-10-27-sam-bakeoff.md](../experiments/2026-10-27-sam-bakeoff.md).

## 1. Default change: `EstimatorConfig.series_count = "min"` (was, in effect, "one")

- **Bug:** some task configs put a whole series of objects under ONE label. sweep_blocks' `rigid2` (small_cube,
  `select_instance_nums [3, 5]`, `label_prefix cube`) becomes `cube_0..cube_4` in every layout, and classify_objects'
  `rigid0` becomes 3 categories x 1-3 items (`cat0_*`, `cat1_*`, `cat2_*`). B1's `label_groups` counts the config's
  labels, so it searched for exactly one cube and one classify item. Integration's genuine-5.1 sweep runs "missed 2 of
  3 cubes" (4 of 5 on 100002) identically in v2 and v3. The cubes were in B1's foreground all along (blob IoU 0.86).
- **Fix:** `series_count` = `one` (old) | `min` (the config's minimum, the new default) | `sam` (distinct SAM 3.1 text
  masks of the group's own vocabulary, rounded up to whole category sets, clamped to the config's range; `min` without
  a SAM server). A single-prefix series is reported under the layout's own labels (`cube_0..`, numbered by x), which
  the checker's prefix lookups find. Per-category prefixes keep the config label: which category the generator
  numbered first can't be observed.
- **Scorer:** `eval_g1.score_record` dropped series objects. Their GT labels (`cube_3`) are not config labels. They
  are now scored under the config label (`eval_g1.series_labels` / `gt_label`). Before the fix, sweep_blocks had 69 of
  107 objects unscored, and classify_objects had all 69. No task in d0 / d0_51 / d0_ext has a series, so the G1
  numbers on those sets are unaffected.
- **Which tasks have a series:** exactly 5 configs (`scripts/perception/sam/series_tasks.py`).
  - sweep_blocks
  - classify_objects
  - classify_objects_by_language (its rigid0 has no catalogue geometry, so B1 skips it)
  - arrange_largest_number(_random): mats, `linked_count`. Not handled: the count follows the number cards and the
    group has no instance range.
- **Evidence:** 29 frame-0 scenes; 25 were rendered for this in the SAM slot (`scripts/perception/sam/render_series.sh`,
  6.0 proxy, `~/dojo-data/sam/d0_series`), plus 4 genuine-5.1 sweep frames. Within tolerance (fixed / broken vs one):
  - one: sweep_blocks 56 / 107, classify_objects 8 / 69
  - min: 92 and 25 (fixed 46 / broken 0)
  - sam: 103 and 30 (fixed 60 / broken 0)
- **No other task changes:** with `min`, d0_51 + d0_ext + coin + laptop (222 frames, 1098 objects) match B1 on every
  object's pose, error, flags and identity. The one exception is a single identity-margin value that differs in the
  4th decimal (0.1323 vs 0.1324, GL float noise).
- Integration confirms on a G3 sweep run that the runtime and the twin accept `cube_k`.

## 2. SAM flags (default off) and how SAM 3.1 loads

- **Loading SAM 3.1:** the Comfy-Org repack (`checkpoints/sam3.1_multiplex_fp16.safetensors`) keeps Meta's own keys
  (`detector.*`, `tracker.model.*`), so no remapping is needed. `sam3.model_builder.build_sam3_multiplex_video_predictor`
  loads it from a `.pt` copy; the only missing keys are RoPE `freqs_cis` buffers. Two quirks:
  - `handle_request(start_session)` passes `offload_state_to_cpu`, which 3.1's `init_state` rejects. We call
    `model.init_state` directly.
  - `add_prompt`'s output cache lags one call. We take the tracker's own masks from `add_new_points`.
- **Text prompts:** the detector under `Sam3Processor`.
- **Points:** the tracker's interactive head on a one-frame "video".
- **SAM 2.1:** Meta's `sam2` code, `SAM2ImagePredictor`.
- **One GPU process serves all estimator workers:** `python -m dojo.perception.sam_masks serve` (unix socket,
  `DOJO_SAM_ADDR`). Setup: `scripts/perception/sam/setup_venv.sh`.
- **Estimator flags:**
  - `sam_fg`: union / trim / gate / replace of the head foreground with SAM 3.1 text masks.
  - `sam_propose`: REAL_RSI's proposer on our fits. Clicks at each chosen object's centre + 4 offsets, a refit inside
    every plausible mask, the fit agreeing best with its mask wins. It also tries the group's other shapes and B1's
    flip; the flip is taken only when the texture agrees.
- **At runtime:** `DOJO_PERCEPTION_CFG` (#192) carries the flags. A SAM server must run next to the perception service,
  with `DOJO_SAM_ADDR` in its environment.

## 3. Landmines

- `pyrender` pins PyOpenGL 3.1.0. Its array handlers fail on numpy 2 in textured renders (press_by_number:
  `ArgumentError ... No array-type handler`, every frame). Install PyOpenGL 3.1.9, as the deploy venvs have it.
- A silhouette can't tell a lying bottle's cap from its base, and the asset origin sits at one end. A 180-degree flip
  chosen by mask IoU alone moved 4 bottles 24-67 mm. The proposer's flip now needs the texture to agree.
- `pkill -f` / `pgrep -f` patterns over ssh match the ssh shell itself (DEVELOPMENT.md pitfall). It bit again: a wait
  loop on `pgrep -f chain.sh` waited on itself. Wait on a PID.
