## 3. Code (PR #26)

Merged: `feat/dojo-skills4` (639d3c8, incl. hang_on_hooks), `feat/dojo-perception` cb5c3a4, main (bridge #22/#23,
registry #21, agent manual v4, bootstrap). Runtime changes, all config fields; the defaults keep closed2:

- **`place_confirm`**: a refine that contradicts a confident belief needs a confirming, better view (lead's
  principle). A PLACE refine is applied directly only if all of these hold:
  - the shift is <= `place_cap_mm` (12);
  - visible >= `place_min_vis` (0.9);
  - the support was not measured by our own post-place refine since its last pick.

  Otherwise there is ONE re-hover over the found pose, `place_confirm_dz` (5 cm) higher, and a refit seeded from the
  PRIOR (an independent start). The correction is applied only if both fits agree within `place_agree_mm` (5);
  otherwise the belief is kept. Shifts < 3 mm that would need a look are dropped. If skills has no re-hover left,
  the belief keeps the prior.
- **`verify_select="risky"`** wraps the Skills instance's `verify_choose`:
  - verified: places, repeated picks of an object, and picks whose last refine was not ok / not confirmed / lost;
  - other picks run candidate 0 unverified, with an empty `on_verified`. The belief then uses the kinematic predictor,
    and the next place's twin loads from the at-rest checkpoint and replays the pick as its prefix.
  - Events `verify_select`; the report gains verify-s and verified / skipped segment medians.
- **Task-2 coverage.**
  - The runtime had no perception vocabulary for stack_blocks_by_language, plug_in_charger or make_kong. Added
    (instruction patterns only); `cover_blocks` stays separate.
  - make_kong in mode B could only time out: `declare_kong` waits for a face-up tile, and the belief never sees the
    opponent's discard.
  - **`watch`** fixes that. It adds a perception service op `watch` (frame 0 vs now, head view only). The make_kong read
    is perception's `task_state.kong_discard`; vocabularies without a read answer `supported: false` once and are
    never called again. While nothing is held, the provider calls it every `watch_every` (4) steps. Two equal confident
    reads lay the knocked tile in its asset's face-up place pose where it stood.
- **Bridge.**
  - `dojo.bridge.smoke.JointStepsSmoke` (runbook 4.0): base + wrist-roll joints out and back at 0.18 rad/step, gripper
    toggles, one chunk per phase.
  - `joint_steps_chunks` now keeps the server's per-chunk `tracking_rad` / `tracking_max_rad` / `max_step_dq` /
    `grip_change_while_moving`.
- Tests: +6 (place confirm both ways, the small / partial / measured-support / noise cases, the off default; risky
  selection; watch; smoke on the fake server).

- **Agentic perceiver** (perception R&D's `dojo.perception.agentic`; merged feat/dojo-perception-rnd 8ff0581, additive):
  - service ops `agentic_estimate` (B1 = the service's own estimate, then their agent + render-and-compare) and
    `needs_agent`;
  - `RuntimeConfig.agentic="budget"` (default "off"), `agentic_max` (default 2; the queued jobs pass 3):
    - frame 0 is agentic;
    - then perception's `needs_agent` decides once after the looks / search (trigger `after_looks`) and at each
      re-estimate after a confirmed divergence (`risk`), while estimates remain.
  - Every gate decision is an `agentic_gate` event with its trigger. Per-call usage goes to the report and eval rows:
    `agentic`: tag, result, calls, tokens, agent_s, model. Model claude/claude-sonnet-5-5 via omniroute (lead-approved).
  - Guard on compute3 (`integ2_agentic_guard.sh`): it drops the remaining agentic jobs above 780 calls (cap 900) or
    above a mean of 12 calls per episode after 10 episodes.

- **Episode tracker** (`tracker`: auto = on iff agentic budget | on | off; `dojo/runtime/track.py`). Perception's
  `Tracker` decides which B1 re-read poses the belief takes at three points: the look-fused record, the scan record,
  and the re-estimate after a confirmed divergence. It applies rules 2/3 (jitter, only-touched-moves) and relocation.
  "Touched" is the runtime's own record: picked, released, or moved > 4 mm by a twin prediction since the last good
  reading (an accepted refine, post-place ok, an accepted re-read).
- **held_look** (`held_look`: off | b1 | b1_then_agent). Once per grasp, after a 4 cm lift, the service op calls
  perception's `agentic.j1.held_look_impl` on the arm's wrist frame. A confident "not held" takes the object out of
  the jaws in the belief (it is dropped where it was grasped), so the pick's own check fails and the job re-picks.
- **Scan pose** (`scan`: off | trigger | always). Both wrists go in parallel to perception's frozen scan joints
  (12 + 2 settle steps from home, <= 0.16 rad/step), followed by a scan-primary estimate (`estimate_with_scan`).
  - Trigger: a not-found label, hidden_frac >= 0.2 or risk >= 0.5, plus the step gate (<= 12% of step_lim >= 300); a
    not-found label always scans.
  - The first skill starts from the scan pose.
  - It needs the scan-aware head background, so the default stays off.
- Agent calls are logged per trigger in `report["agentic"]`: frame0 / after_looks / risk / held.

- **Vocabularies** (journal-worthy default changes, both for instructions the table does not resolve):
  - `perception_vocabulary` falls back to the catalogue (`dojo/runtime/vocab.py`: the candidate set whose objects
    the instruction names). Before, such an instruction returned None and mode B ended at "no_vocabulary".
  - `RuntimeConfig.vocab_explain` (default on) handles ambiguity: when the table and the fallback disagree, or the
    fallback's runner-up is within 15% of its top, B1 runs on frame 0 once per candidate set (at most 3). The set
    whose estimate explains the scene best wins (found share x mean confidence); event `vocab_explain`.
  - Rates, from `tests/fixtures`:

    | set | table | fallback alone | both |
    |---|---|---|---|
    | 55 public templates | 43 | 51 | 55 |
    | 44 paraphrases | 23 | 43 | 44 |

  - Lane vocabularies: every task of Ilia's lane (LANES.md) is in the table.
- **search_lost fix**: a lost object's find counts only when it is refine-confirmed, or a full-fuse find within 10 cm
  of the belief. search_lost stays off in the queue configs until an A/B.
