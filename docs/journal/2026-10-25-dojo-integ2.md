## 3. Code (PR #26)

Merged: `feat/dojo-skills4` (639d3c8, incl. hang_on_hooks), `feat/dojo-perception` cb5c3a4, main (bridge #22/#23,
registry #21, agent manual v4, bootstrap). Runtime changes, all config fields; the defaults keep closed2:

- **`place_confirm`**: a refine that contradicts a confident belief needs a confirming, better view (lead's
  principle). A PLACE refine is applied directly only if all of these hold:
  - the shift is <= `place_cap_mm` (12);
  - visible >= `place_min_vis` (0.9);
  - the support was not measured by our own post-place refine since its last pick.

  Otherwise there is ONE re-hover over the found pose, `place_confirm_dz` (5 cm) higher, and a refit seeded from the
  PRIOR (an independent start). The correction is applied only if both fits agree within `place_agree_mm` (5);
  otherwise the belief is kept. Shifts < 3 mm that would need a look are dropped. If skills has no re-hover left,
  the belief keeps the prior.
- **`verify_select="risky"`** wraps the Skills instance's `verify_choose`:
  - verified: places, repeated picks of an object, and picks whose last refine was not ok / not confirmed / lost;
  - other picks run candidate 0 unverified, with an empty `on_verified`. The belief then uses the kinematic predictor,
    and the next place's twin loads from the at-rest checkpoint and replays the pick as its prefix.
  - Events `verify_select`; the report gains verify-s and verified / skipped segment medians.
- **Task-2 coverage.**
  - The runtime had no perception vocabulary for stack_blocks_by_language, plug_in_charger or make_kong. Added
    (instruction patterns only); `cover_blocks` stays separate.
  - make_kong in mode B could only time out: `declare_kong` waits for a face-up tile, and the belief never sees the
    opponent's discard.
  - **`watch`** fixes that. It adds a perception service op `watch` (frame 0 vs now, head view only). The make_kong read
    is perception's `task_state.kong_discard`; vocabularies without a read answer `supported: false` once and are
    never called again. While nothing is held, the provider calls it every `watch_every` (4) steps. Two equal confident
    reads lay the knocked tile in its asset's face-up place pose where it stood.
- **Bridge.**
  - `dojo.bridge.smoke.JointStepsSmoke` (runbook 4.0): base + wrist-roll joints out and back at 0.18 rad/step, gripper
    toggles, one chunk per phase.
  - `joint_steps_chunks` now keeps the server's per-chunk `tracking_rad` / `tracking_max_rad` / `max_step_dq` /
    `grip_change_while_moving`.
- Tests: +6 (place confirm both ways, the small / partial / measured-support / noise cases, the off default; risky
  selection; watch; smoke on the fake server).
