# SO-101 rig: real arm with a camera on the gripper

controlr drives a LeRobot SO-101 follower (5 joints + gripper, Feetech STS3215) whose only
camera rides on the gripper. The model sees the wrist image, a STATE line and a VIEW line, and
replies `MOVE ee_delta dx dy dz` / `GRIP` / `STATUS` as everywhere else.

```
 rig (sp@192.168.1.22, LAN)              Mac (jump host)         controlr (local)
 so101 server (LeRobot's python)   <-  ssh -L 7811  <-  ssh -L 7811  <-  So101Robot  -> LLM router
   Feetech bus, wrist camera, stop rules                                 envelope, IK, loop
```

The rig cannot reach the LLM router, so controlr runs elsewhere and reaches the server
(localhost-only, HMAC key) through ssh tunnels.

## Parts

| File | What |
|---|---|
| `controlr/robot/so101/kinematics.py` | URDF FK (TheRobotStudio `so101_new_calib.urdf`), DLS IK, straight-line joint paths, the 5-joint orientation rule, default wrist-camera pose |
| `controlr/robot/so101/server.py` | runs on the rig in LeRobot's env: bus + camera, min-jerk streaming at 50 Hz, stop on a blocked joint, settle, fresh frame |
| `controlr/robot/so101/client.py` | `So101Robot` (`robot.backend: so101`) |
| `controlr/prompts/system_v3.md` | the manual for a moving camera (VIEW line instead of fixed axis directions) |
| `configs/so101*.yaml` | rig defaults, `so101_touch`, `so101_pick` |
| `scripts/so101_server.sh` | start the server on the rig |
| `scripts/so101_jog.py` | first-motion check, no LLM |
| `scripts/so101_calibrate.py` | ChArUco intrinsics + hand-eye |
| `scripts/so101_verdict.py` | operator verdict for an episode |

## Geometry the model gets

* Base frame = URDF `base_link`: origin on the table under the base, x forward, y left, z up;
  table z = 0. TCP = `gripper_frame_link`, between the jaw tips.
* LeRobot's `DEGREES` joint reading (zero = middle of the calibrated range) is the URDF's
  "new calibration" zero, so encoder angles go into FK unchanged.
* 5 joints: the tool keeps a fixed pitch (`tool_pitch_deg`, default 60 below horizontal) and
  roll (`tool_roll_deg`, default 90: the stock wrist camera upright, image up = forward, jaws
  closing sideways) and always points away from the base (`kinematics.reachable_rotation`).
  `rotation: yaw` works only with `tool_pitch_deg: 90` (straight down: reach z <= ~100 mm).
  Reachable at pitch 60: x ~140..380 mm, z up to ~150 mm.
* VIEW line every turn: which way +x / +y run in the current image from the jaw tips (the
  camera moves, so the manual cannot state fixed directions).

## Safety (in code, below the model)

1. `CartesianEnvelope`: workspace box, table clearance, 50 mm per MOVE line (`configs/so101.yaml`).
2. Client: IK every 5 mm; an unreachable stretch shortens the move (WARN); the target
   orientation is always the reachable one.
3. Server: goals clamped to the calibrated range minus 3 deg; peak joint speed <= 1 rad/s;
   TCP speed `safety.max_tcp_speed_m_s` (0.05 m/s); a joint more than 12 deg behind its goal
   for 3 ticks (or above `current_stop_ma`, off until tuned) = blocked → the arm freezes where
   it is (STOP); power-up sets Goal = Present before torque on.
4. Ctrl-C on the server: freeze; twice within 3 s: torque off (THE ARM FALLS) and exit.
   `shutdown` op / normal exit: slow move to the rest pose, then torque off.
5. **A human at the arm's power switch for every motion.** The arm is light and slow, but its
   reach covers whatever stands in front of it — clear the workspace (the rig laptop sat in it
   on 2026-10-14).

## Run it

On the rig (once per session; the camera must be free — close browser tabs using it):

```bash
cd ~/controlr-so101
CONTROLR_SO101_AUTHKEY=$(cat ~/.so101_authkey) nohup scripts/so101_server.sh > server.log 2>&1 &
```

Deploy = copy `controlr/__init__.py`, `controlr/robot/so101/{__init__,protocol,server}.py` and
`scripts/so101_server.sh` to `~/controlr-so101/` on the rig (no install: LeRobot's env runs it).

Tunnels (the rig's ssh needs a password from the Mac; the Mac is `ssh mac`):

```bash
ssh mac 'ssh -fN -L 127.0.0.1:7811:127.0.0.1:7811 sp@192.168.1.22'   # Mac -> rig
ssh -fN -L 127.0.0.1:7811:127.0.0.1:7811 mac                          # here -> Mac
```

controlr (same key in the environment):

```bash
export CONTROLR_SO101_AUTHKEY=...                     # = ~/.so101_authkey on the rig
uv run python scripts/so101_jog.py                    # first motion: home, +-20 mm per axis, grip
uv run controlr run -c configs/so101_touch.yaml       # live LLM
uv run controlr run -c configs/so101.yaml --set task.instruction="..."
uv run python scripts/so101_verdict.py runs/<run_dir> success|partial|fail "note"
```

Dry run without hardware: `scripts/so101_server.sh --fake` (or `python controlr/robot/so101/server.py
--fake`) and `controlr run -c configs/so101_touch.yaml --fake-llm`.

## Calibration

`uv run --with opencv-contrib-python python scripts/so101_calibrate.py board board.png` → print
at 100 %, measure a square; `... intrinsics --square-mm <s>` (no motion: wave the board);
`... handeye --square-mm <s> --board-x 0.26` (board flat on the table; the arm visits 15 poses).
Output `~/.config/controlr/so101_wrist.json` → `robot.params.camera_calib`. Its check numbers:
the board origin's z in the base frame should be ~0 mm (table), the spread over views a few mm.
Until then the camera pose is the stock mount from `so101_new_calib_camera.urdf` (the VIEW line
directions are right, the pixel lengths approximate) — keep `renderers: [raw]`.

## Known gaps

* No automatic success check: `trust_done` + operator verdict.
* `current_stop_ma` is off: log the peaks (`turns.jsonl` → `backend.runs[].peak_current_ma`)
  on free moves first, then set it above them.
* The gripper's width map is linear 0..100 % → 0..70 mm (not measured).
* Gravity sag is not modelled: the arrival WARN (> 10 mm) reports it.
