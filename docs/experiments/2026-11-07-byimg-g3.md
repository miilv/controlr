## Registration (before panel outcomes)

Hypothesis: refreshing the hook after transit and retaining the wall brace during
initial loading reduces basket drift and supports a level lift after depositing
the pictured target. This is physics-only development, not a camera adoption.

Compare A (`belt_container=on,belt_deposit=on,belt_lift=off`) with B (same,
`belt_lift=braced_hook`). Both use `--routes basket_image`, GT mode A, no verifier,
no model calls. The route is common to both arms so this comparison isolates lift.
All defaults stay unchanged; neither configuration is a board candidate.

Fresh layouts: simlab/v15, variant 7, salt `byimg-20261107-fresh`, ids
100030–100039, one deterministic episode per arm on compute3. Pilot ids
100020–21 are excluded. Generate with `scripts/skills/byimg/generate.py`.
No historical layout file or protected data is used.

Use the same immutable settled file in both arms. Ordinary presettle rejects
belt travel (40 mm per rest window); `scripts/skills/byimg/settle.py` instead
uses the existing `raw_at_rest` belt-relative check after 250 physics steps,
removes common horizontal travel relative to the load snapshot, writes settled
poses, and checks a stable reload. This does not stop the belt or modify physics.
If any record fails, report it and generate fresh replacement draws before
viewing either outcome; do not choose layouts by skill success.

Report mean score (0–100), sample SD, successes, per-pair score wins/losses/ties

write a parked camera spec. No camera jobs are authorized by this registration.

Resources: at most two BYIMG physics jobs, light locks, per-start who/GPU/disk
admission (<=24576 MiB used, >=10 GB free), 8G/600% systemd scopes. All remote
writes under `~/controlr-byimg` and `~/dojo-data/byimg`. Zero LLM spend.

## Probes and limits

Two raw-layout target pilots (100020–21) failed target intercept before testing
the lift. Isolated basket probes: normal stop + braced hook 4.4 mm bottom rise;
near-wall-only stop + hook -2.1 mm. Deeper 40/60/80 mm handle pinches closed,
but their requested 130 mm lifts failed IK. A two-wall probe found 80 far-wall
grasps, all unreachable. Pulling farther toward y=-0.20 slid through the pinch
instead (actual basket y=-0.055); the same far-wall grasps still failed IK.
These are mechanism diagnostics, not extra paired observations or successes.

The settled files preserve post-load horizontal belt phase (the extra 250-step
travel is removed relative to the first load snapshot). Loading the frozen
snapshot advances the belt again during reset. For example 100030's basket x
is -0.119 m authored and +0.087 m in the settled record. This is an explicit
limitation: the panel compares the same frozen inputs, but its absolute failure
rate is not directly comparable to historical raw-v15 screens. A future phase-
preserved settling protocol should remove total belt travel relative to authored
positions and validate a fresh panel; do not rewrite these measured inputs.

The empty frame-0 record and absent genuine-5.1 background remain separate
camera blockers. The opt-in route consumes existing observed roles and cannot
fix missing objects. BACKLOG specifies compute6 follow-up. No perception code
was changed. Physics-only traces replace videos here because compute3 RTX is
known to crash; no renderer was invoked.

## Disposition

This attempt does **not** establish a physically working chain. Keep the
experiment off. The next physical lever needs a basket restraint that actually
survives contact and drag, with reachable support on both sides; target
interception also remains a bottleneck. Do not book camera jobs for this hook.
