# BYIMG: braced hook versus handle pinch in G3 mode A

## Registration (before panel outcomes)

Hypothesis: refreshing the hook after transit and retaining the wall brace during
initial loading reduces basket drift and supports a level lift after depositing
the pictured target. This is physics-only development, not a camera adoption.

Compare A (`belt_container=on,belt_deposit=on,belt_lift=off`) with B (same,
`belt_lift=braced_hook`). Both use `--routes basket_image`, GT mode A, no verifier,
no model calls. The route is common to both arms so this comparison isolates lift.
All defaults stay unchanged; neither configuration is a board candidate.

Fresh layouts: simlab/v15, variant 7, salt `byimg-20261107-fresh`, ids
100030–100039, one deterministic episode per arm on compute3. Pilot ids
100020–21 are excluded. Generate with `scripts/skills/byimg/generate.py`.
No historical layout file or protected data is used.

Use the same immutable settled file in both arms. Ordinary presettle rejects
belt travel (40 mm per rest window); `scripts/skills/byimg/settle.py` instead
uses the existing `raw_at_rest` belt-relative check after 250 physics steps,
removes common horizontal travel relative to the load snapshot, writes settled
poses, and checks a stable reload. This does not stop the belt or modify physics.
If any record fails, report it and generate fresh replacement draws before
viewing either outcome; do not choose layouts by skill success.

Report mean score (0–100), sample SD, successes, per-pair score wins/losses/ties
(10-point threshold), success flips, steps, failure stages, missing meshes and
infrastructure failures. Run all 10 pairs; no early stop for poor results.
A large gain means >=5 mean points, wins >=2*losses and >=2 net wins; only then
write a parked camera spec. No camera jobs are authorized by this registration.

Resources: at most two BYIMG physics jobs, light locks, per-start who/GPU/disk
admission (<=24576 MiB used, >=10 GB free), 8G/600% systemd scopes. All remote
writes under `~/controlr-byimg` and `~/dojo-data/byimg`. Zero LLM spend.

## Checker read before implementation

Read compute3's installed RoboDojo `task/RoboDojo/tasks/pick_from_conveyor_by_image.py`,
`env/reward_manager/reward_manager.py` and `func_parser.py`.
`run_reward` registers one conjunction: target on basket bottom (world bbox
bottom gap -0.01..0.04 m and basket footprint covers target), and target origin
z > reset origin z +0.08 m. The task registers no process-score ladder.
Thus a lifted empty basket or a deposited target alone earns no partial score.
The predicate measures target lift, not basket lift directly. Thresholds stay
out of skill prompts and routing text.
