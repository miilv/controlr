# 2026-10-28 — twin-trained instance segmenter (stream S): GT-mask ceiling, genuine-5.1 training set, trained model

Stream S of the perception-to-95 % push (`/tmp/dojo-team/PERCEPTION_95.md`). Branch `feat/dojo-seg-twin`. Journal:
[../journal/2026-10-28-dojo-seg-twin.md](../journal/2026-10-28-dojo-seg-twin.md). 0 LLM calls.

## Question

Does an instance segmenter trained only on our simulator's renders find and identify the objects B1 misses, on
genuine-5.1 frames it never saw? And does it help B1 as a proposer? The model's class is the catalogue asset
(`Type/category/idx`). The 10-25 options report estimated +4-6 pp of objects for it, with an upper bound of 11 %
(missed + identity + flips). It was never built.

## Data and protocol

- **Training layouts.** These are new random draws of ids 100030-49. `gen_layouts.generate(..., variant=v)` with v >= 1
  draws sub-seeds `id * 1000 + 100 + 40 (v - 1) + attempt`, which stay inside the id's own block. So no stored or
  measured layout is reproduced: v0 is byte-identical to the stored records, which I checked on deposit_coin and
  hang_mugs. Ids 100010-19, 100050-99 and >= 100100 are refused (`seg_render.parse_ids`).
- **Evaluation frames.** d0_51 (genuine 5.1) and d0_ext (6.0 proxy), ids 100000-09 + 100020-24 only. Frame 0 is used
  for the end-to-end runs. The component metrics use d0_51 frames 0-3 and d0_ext frames 0-1, on all three cameras.
- **Labels.**
  - Training: Isaac's own `instance_id_segmentation_fast` annotator on RoboDojo's render products (`seg_render`),
    mapped to GT objects by prim path. Arms and other prims get their own codes.
  - Evaluation GT: GT-pose renders (catalogue meshes, GT cameras, FK arms, the table slab as an occluder) on CPU through
    Mesa's llvmpipe, so no GPU process is used.
  - The two agree at IoU 0.94-1.00 per object on the pilot frames.
- **Scorer.** eval_g1 through the SAM bake driver (`scripts/perception/seg/bake_seg.py`), paired against B1 on the same
  frames. B1 runs on CPU silhouettes (`DOJO_GL=0`, no GPU). On these frames it scores 891 within tolerance, against 903
  for GPU GL.

## 1. Ceiling: B1 + `seg_propose` with GT masks (a perfect segmenter)

A fake server (`scripts/perception/seg/oracle_server.py`) answers `seg_twin`'s `detect` with the GT masks (>= 30 px)
and their asset classes. The estimator's code is the same as with the model.

| arm (201 scenes, 1013 objects) | within tol | gross | missed | phantoms | fixed / broken | scenes all right |
|---|---|---|---|---|---|---|
| B1 (CPU silhouettes) | 891 | 80 | 14 | 39 | - | 125 |
| oracle masks + `seg_propose` v1 (B1's `_propose` on the mask) | 932 | 51 | 9 | 29 | 42 / 1 | 144 |
| oracle masks + `seg_propose` (final: direct fit on the mask) | **950** | **39** | **4** | **18** | **59 / 0** | **151** |
| for scale: SAM 2.1-S proposer vs its B1 (GPU GL), same objects | 903 -> 927 | | | | 25 / 1 | 128 -> 143 |

Per task, final (within tolerance, B1 -> oracle):

| task | n | B1 -> oracle | |
|---|---|---|---|
| organize_table | 81 | 55 -> 71 | gross 18 -> 6, phantoms 14 -> 4 |
| build_tower | 120 | 99 -> 114 | gross 18 -> 5 |
| pack_objects_into_box_random | 75 | 48 -> 58 | gross 25 -> 17 |
| general_pickup | 10 | 5 -> 10 | |
| stack_blocks | 45 | 35 -> 39 | |
| stack_bowls | 45 | 38 -> 41 | |
| store_tools_in_toolbox | 50 | 48 -> 50 | |
| others | 587 | +3 | 0 broken anywhere |

- **Complementary to SAM.** Only 10 of the 59 fixes are SAM-proposer fixes too.
- **Left with perfect masks: 63 objects.**
  - push_T: 5 Ts under the home grippers, where no mask shows them.
  - pack_random: shoes and cars read 180 deg backwards. No flip passes the texture check.
  - organize_table: 6 gross.
  - stack_bowls: 5 overshoots.
- **What made v1 -> final.** Three changes, each from a decision trace (`_perception.sam.seg.trace`) on 8 failing
  scenes:
  - the mask is fitted directly, with the mask as the head foreground. B1's `_propose` prefilters and its refine on
    the full foreground had pulled fits off the mask (IoU 0.0-0.47);
  - the mask's pixels count as known. organize_table's scene background blanks the mouse mat's area, which made the
    mouse "hidden";
  - B1's occluded guesses may move to an unexplained mask of their group.

## Reproduce

```bash
# training renders (genuine 5.1, RoboDojo's python, one job per task in the rendered lane)
SEG_REQUIRE_IDLE=0 SEG_MAX_S=1680 scripts/perception/seg/render_queue.sh "--ids 100030-100049 --variants 1 --poses 4" TASK ...
# YOLO dataset + training (perception venv + torch + ultralytics)
python scripts/perception/seg/export_yolo.py --render ~/dojo-data/segtrain/render --out ~/dojo-data/segtrain/yolo_v1 --val-ids 100049
SEG_GPU_LOCK=~/dojo-gpu.lock scripts/perception/seg/train_job.sh .venv/bin/python v1 ~/dojo-data/segtrain/yolo_v1/data.yaml \
    --model ~/dojo-data/segtrain/models/yolo11s-seg.pt --epochs 60 --batch 16
# component metrics on held-out frames (GT masks on CPU first)
python scripts/perception/seg/eval.py gt --out ~/dojo-data/segtrain/eval_gt --sets d0_51 --frames 0,1,2,3
python scripts/perception/seg/eval.py gt --out ~/dojo-data/segtrain/eval_gt --sets d0_ext --frames 0,1
python scripts/perception/seg/eval.py pred --gt ~/dojo-data/segtrain/eval_gt --weights W --classes classes.json --out rows.jsonl
python scripts/perception/seg/eval.py table rows.jsonl
# end to end: the server, then B1 with and without the flag (and the GT-mask oracle)
python -m dojo.perception.seg_twin serve --sock S --weights W --classes classes.json
DOJO_SEG_ADDR=S python scripts/perception/seg/bake_seg.py run --out DIR --cfg '{"seg_propose": "on"}' [--gl gpu]
python scripts/perception/seg/oracle_server.py --gt ~/dojo-data/segtrain/eval_gt --sock O
python scripts/perception/sam/bake.py summary DIR BASE_DIR; python scripts/perception/seg/bake_seg.py transitions DIR BASE_DIR
```
