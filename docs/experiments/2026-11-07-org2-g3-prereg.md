# ORG2: fresh paired G3 panel of the general arrange capabilities (pre-registration)

Registered before any panel episode runs. Physics-only G3 mode A (true identities and poses from the simulator), no
verifier, no LLM, compute3 light locks (light7 / light8, at most two jobs, admission GPU used <= 24 GiB and disk >= 10
GB, 8 G / 600 % scopes, `timeout -k 60`). Dev tuning used only the unsalted settled records 100000-07 and 100009
(`docs/experiments/2026-11-07-org2-g3.md`); the panel's records were generated with a fresh salt and never opened by
a policy run before this registration.

## Question

Do the default-off general capabilities of stream ORG2 (planned two-point pushes, clear push goal, arrange retry, the
mesh support surface, torso grasps with palm-aware approach / squeeze / slip memory, base-radius stand positions,
checked place vias, axis-first retreat; with the existing free-space proposer) raise organize-table G3 score on fresh
layouts, and how close does B come to PyRUA-RSI's seed-0 score (93.5; REPRO's same-layout bar replaces it in the
report once `rsi-yardstick/per_cell.json` has it)?

## Layouts (frozen)

[design.json](data/org2/design.json): salt `org2-g3-20261107-f3c691ec4d1ac985d5e18bd0d74020b8`, ids 100000-09 and
100020-29 only (our slices), generated by the unchanged `dojo.simlab.gen_layouts --seed-salt` from main `0144ced`
under a private `DOJO_DATA` (`~/dojo-data/org2/panel`). Raw-record SHA256s are in
[panel-raw.sha256](data/org2/panel-raw.sha256). Default two-pass presettle (`dojo.simlab.presettle`) on a light lock;
every id with settled status `ok` is in the panel, dropped ids are listed in the report; no outcome-based exclusion
and no replacement ids.

## Arms

Both arms run one immutable deployment of the PR head (commit recorded in every row's `code.commit`).

- **A:** all defaults (`--trace` only).
- **B:** `--skill-attr` `push_contact=pair push_plan=sequence push_goal=clear arrange_retry=once place_surface=mesh
  grasp_torso=on stand_offset=base retreat_axis=on plan_world=objects place_via=clear slip_avoid=on`.

Order: for each layout, A then B on the same lane; layouts alternate between the two lanes in ascending id order. One
episode per layout per arm, fresh reset, 1000-step limit. An infrastructure failure (`infra_failure`, a crashed job)
reruns that pair once on the same lane; every attempt is kept.

## Decision rule (score-based default, EXPERIMENTS 7 Nov)

Gain cell organize_table, n = the settled panel (>= 10 pairs required, else the panel is reported as incomplete):

1. pooled B >= pooled A + 5 points;
2. pair wins (B - A >= 10 points) >= 2 x losses (A - B >= 10), wins - losses >= 2.

Success flips are reported alongside. This G3 panel is physics evidence for a camera-slot request, not camera adoption
(the camera A/B, its guard cells and the write audit are separate). Bar comparison: B's pooled mean, sample SD and 95 %
bootstrap interval against 93.5; "near the bar" is not a gate here, it is reported as a number.

## Measured per episode (`scripts/skills/org2_stages.py`, dev scorer)

Final per-item conditions, the most items holding at once with open grippers, the step each item first held and every
later loss with the segment running (interference by order), figure base xy error to the stand origin, figure pick /
carry drift, alarm tilt after release (toppling), keyboard yaw, arrange order and outcomes, steps.
