**Hypothesis:** searching grasp and drop orientations inside the practical X5
workspace reduces unusable targets and raises fill_egg_holder's G3 ceiling.

**Setup:** default-off `egg_reach=search` versus all egg switches off, G3 mode A,
700 steps, the same ten frozen v6 dev layouts as EGG. Controller source `8be287c3`.

post-merge smoke runs are excluded from this frozen panel.

comparison, not a camera test or a preregistered adoption claim. Two workers run
opposite pair order. No score/checker, object masses, safety thresholds or step
budget changes.

## Fixed-request orientation sensitivity

The stripped [PLAN bank](egg2/request-bank.json) contains twelve failed
`place_approach` endpoints in robot-base coordinates from layout 100001. Reproduce:

```bash
uv run python scripts/skills/egg_reach_bank.py \
  docs/experiments/egg2/request-bank.json /tmp/egg2-sensitivity.json
```

Each test preserves the TCP position while perturbing the rotation about each base
axis by ±15, ±30 and ±60 degrees. Native IK uses four deterministic random retries,
nominal wide limits or their intersection with practical bounds. There are no
obstacles or executed actions. Every request's planar distance is 0.380–0.444 m,
inside the 0.60 m practical screen. This is an orientation/branch limitation in the
tested solver, rather than simply excessive planar distance.

Nominal poses: 1/12 feasible under either envelope, reproducing the prior 11/12
failure observation. With the eighteen perturbations, every request has at least
two feasible orientations under practical bounds (2–15 of 19 including nominal).
All eleven failed nominal poses reach the j4 bound in the recorded local solve.
Failed targets include local-solve margins separately from multiseed IK success;
a failed solve has no certified solution margin. Full residuals and per-joint margins are in the [results](egg2/orientation-sensitivity.json).
These rotations are **not** geometry-valid egg release targets or a proof of a
collision-free carry. The skill only adds geometry-preserving round grasps and
axial-spin drop candidates; it never executes arbitrary diagnostic rotations.

## Initial-layout grasp geometry

A CPU-only screen reconstructs all ten settled layouts with the native catalogue.
Across 40 eggs × two arms, the broad round-orientation grid has feasible grasp,
pre-grasp and lift endpoints for 51/80 arm–egg combinations, covering all 40 eggs
with at least one arm. The actual wall-filtered candidate generator retains such
endpoints for 28/80 combinations, covering 24/40 eggs. Per-egg/arm counts are in the
[geometry summary](egg2/geometry-summary.json); full endpoint distance/margin logs
remain remotely in `geometry-endpoints.jsonl`.

These are different candidate sets and approach heights: the broad no-wall grid
uses ordinary pre-grasp distance, while the real generator must clear the rim.
The difference jointly reflects orientation sampling, wall clearance and approach
height; it is not a controlled wall-removal effect. Neither screen validates the
intervening collision-free path or physical grasp. The two-arm reach test already
covers both arms; merely selecting the other arm cannot remove the wall-foot
obstruction. One early auxiliary script failed on an egg outside any container;
its log is retained, and the completed ten-layout script handles that case.

No complete task successes were observed. No instability or infrastructure failures
occurred; no episode exhausted the 700-step budget.

The profile does not raise the ceiling and remains off. No camera pre-registration
is triggered. The twelve-request orientation diagnostic identifies a real endpoint
limitation, but this combined profile does not solve the physical skill. The tested
practical envelope, candidate search and carry/release behavior are confounded
within this one switch; this panel cannot assign regressions to one component.

The lower IK failure fraction does not mean less failed work: total native queries
increase from 14,917 to 45,746, and failed queries from 8,163 to 13,576. Planning
wall time increases by 82%. The screen changes which candidates reach later
planning, so the lower conditional planner failure fraction is not an independent
measure of controller improvement.

Logged final no-pick exits increase from 12 to 18; pick-then-no-drop-plan exits
fall from 9 to 6; recorded `grasp_slip` skill results increase from 3 to 6. These
are attempt events with retries, not mutually exclusive final-egg classifications.
On 100012, target1's drop reports `NOT in a hole` under search despite the same
nominal grasp note; target2 is then picked but has no carry/drop plan. On 100015,
target0/target3 retained endpoints still fail ordinary collision planning. These
illustrate why endpoint reachability alone does not raise the ceiling.
