# 2026-10-25 — scan pose at episode start: B1 with an unoccluded head view

Follow-up to [perception-options](2026-10-25-perception-options.md) §4.1. Question: does a fixed park-and-look pose pair
at episode start shrink B1's largest failure class, objects hidden under the home grippers? Code:
`dojo/perception/scan.py` (pose), `dojo/perception/eval_g1.py` (`--look-primary`, scan frames in the clean
background). Data: our D0 copy (stack_blocks, push_T, build_tower; 25 layouts each). GT is read only by the scorer.

## Pose
- **Definition.** Left wrist camera eye (-0.44, -0.46, 1.06), looking at (-0.34, -0.14, table); the right arm mirrors
  it. Flange poses come from the public mount, joints from IK nearest to home, and the pair is the same in every
  episode.
- **Design search** (FK + robot masks only):
  - head-view occlusion of the object region (x ±0.47, y -0.27..0.10): 0 % at the scan pose vs 12.5 % at home;
  - each wrist camera sees its whole table-front corner zone at about 0.43 m (about 1.1 mm per pixel).
- **Reached in the 5.1 physics twin** (simlab `look_render`, cuRobo): 75/75 layouts, camera within 1.2 cm / 2.7 deg.
  The move out costs 36 env steps with simlab's Mover, and a return about the same. Rendered with the Isaac 6.0 proxy
  (`frame_S1`).

## Result (within tolerance / gross, 325 objects)

| arm | tower (200) | T (25) | pad (25) | stack blocks (75) | all |
|---|---|---|---|---|---|
| frame 0 (B1 today) | 168 / 30 | 21 / 4 | 20 / 4 | 63 / 7 | 272 / 45 |

| scan as the primary view alone, old background | 152 / 43 | 21 / 4 | 12 / 13 | 62 / 12 | 247 / 72 |
| scan primary + frame 0, old background | 171 / 27 | 21 / 4 | 18 / 7 | 62 / 10 | 272 / 48 |
| scan primary alone, scan-aware background | 169 / 28 | 25 / 0 | 14 / 11 | 66 / 6 | 274 / 45 |

| **same + frame-0 fill for objects the scan view misses** | **187 / 10** | **25 / 0** | **22 / 3** | **70 / 2** | **304 / 15** |

- **The background requirement.** B1's robot-free head background is a masked median. Its "unseen" pixels are read
  as unknown, including any objects the scan reveals there. Our D0 copy held only frame 0 + the scan frame, so its
  background had never seen the zone under the home grippers ("old background" rows).
  - The canonical backgrounds (`~/dojo-perception-data/bg_folds`, built from all D0 frames 0-3, where frames 1-3 move
    the arms) have seen that zone. With them the scan path does slightly better: frame 0 269 / 44 -> scan primary +
    frame 0 300 / 20 -> + fill **307 / 13**.
  - So no new background is needed, for the 6.0 proxy or for 5.1. `bg_folds_51` and the J1 install's `bg/` are built
    the same way: their unseen pixels are only the image's bottom strip (rows 397-472), below the table front.
  - `scan.patch_background` and `bg_folds_scan/` (built from frame 0 + scan frames) stay as alternatives.
- **The conservative fuse cannot add objects.** It only refines frame 0's objects, so it shows no gain by
  construction. Proposals come from the primary head view, which is why the scan must be the primary view.
- **Pads are missed more often from the scan view** (7 of 25): a flat grey pad is weak in the farther wrist views. The
  frame-0 fill (take frame 0's reading for an object the scan estimate does not find) recovers them.
- **Net effect:** within tolerance 83.7 % -> 93.5 %, gross errors 45 -> 15 (-67 %), for about 36 env steps out
  (+ about 36 back if the policy returns home), 0 LLM calls.

## Live agentic test (Sonnet 5.5, 79 LLM calls)
Setup:
- the same frozen runner, plus the scan observation (`runner_robodojo_v2.md`, selected only when a second observation is
  present);
- hint = scan-primary B1 (`estimate_with_scan`);
- the agent's free-text categories map to the hint's vocabulary, and agent points within 1 cm of B1 (or 2 cm of a
  confident B1 object) take B1's fitted pose.

24 hard D0 scenes (stack 10, push 10, tower 4; 82 objects), the same scenes as the frame-0-only runs in the options
report:

- Per task (within tolerance / gross): stack 29/30 and 0 gross; push 20/20 and 0 gross; tower 23/32 and 2 gross.
- Against B1 frame 0: 17 gross errors fixed, 1 broken.
- Cost: 3.5 LLM calls median per call (max 6), 40 s median (p90 84 s), 50k prompt tokens.
- H2 in the scan frame on top adds nothing measurable here.

### The 2 remaining gross errors (both build_tower `block4`, the green prism at the left table edge, x = -0.43)
- **100024: no arm found it.** B1 frame 0, B1 scan-primary and the agent all missed it. That needs a look at the
  corner (a perception-side look_plan request), not a better reading.
- **100022: the only object the agent broke.**
  - B1 scan-primary found it at confidence 0.24, together with a phantom stacked pillar (z 0.822).
  - The agent reported 7 pieces (8 expected) and left the prism out.
  - The duplicate-safe re-add only restores an unmentioned B1 object while the agent reports fewer objects of that
    kind than B1, and B1's count (6) includes the phantom.
  - A re-add up to the vocabulary's expected count would bring back both the prism and the phantom. Choosing between
    them (confidence picks the phantom) needs a support / identity rule that one case cannot validate. Left as is.
